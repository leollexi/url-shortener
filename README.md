# 🔗 URL Shortener

Сервис сокращения ссылок (как bit.ly), полностью контейнеризован с помощью Docker.
Учебный DevOps-проект: демонстрирует работу с многоконтейнерным приложением.

## Архитектура

```
   Браузер
      │ :8080
      ▼
┌───────────────┐     ┌───────────────┐     ┌───────────────┐
│     Nginx     │────▶│   Flask app   │────▶│  PostgreSQL   │
│ reverse proxy │     │  (Python)     │     │  (база данных)│
└───────────────┘     └───────────────┘     └───────────────┘
   доступен снаружи      внутри сети            внутри сети
                                                + volume (данные)
```

Наружу торчит только Nginx. Приложение и база данных изолированы во внутренней
сети Docker и общаются по именам сервисов через встроенный DNS.

## Стек
- **Nginx** — reverse proxy (точка входа)
- **Flask + Gunicorn** — веб-приложение (Python)
- **PostgreSQL** — хранение ссылок
- **Docker Compose** — оркестрация всех сервисов

## Возможности
- Сокращение длинных URL в короткие коды
- Редирект по короткому коду на оригинал
- Подсчёт кликов по каждой ссылке
- Веб-интерфейс + JSON API
- Данные сохраняются между перезапусками (volume)

## Запуск

```bash
docker compose up -d --build
```

Открой в браузере: http://localhost:8080

## API (примеры curl)

```bash
# Создать короткую ссылку
curl -X POST http://localhost:8080/shorten \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.google.com"}'
# -> {"short_url": "http://localhost:8080/Ab3xY9", "code": "Ab3xY9"}

# Перейти по короткой ссылке (редирект)
curl -L http://localhost:8080/Ab3xY9

# Проверка здоровья
curl http://localhost:8080/health
```

## Управление

```bash
docker compose ps          # статус сервисов
docker compose logs -f app # логи приложения
docker compose down        # остановить (данные БД сохраняются в volume)
docker compose down -v     # остановить + удалить данные БД
```

## Чему учит проект
- Многоконтейнерная архитектура (Docker Compose)
- Reverse proxy (Nginx)
- Связь сервисов по DNS-именам
- Постоянное хранение данных (volume)
- Изоляция: наружу открыт только нужный порт
- Сборка своего образа (Dockerfile) + готовые образы
- Healthcheck для проверки готовности БД
